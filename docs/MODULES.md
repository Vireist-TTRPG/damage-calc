
# Документация: создание и настройка модуля Irreality

## 1. Что такое модуль

Модуль — один JSON-файл в папке `modules/`, описывающий **данные и правила** сеттинга: пластины, патроны, стволы, режимы, дистанции, укрытия, словари атрибутов/навыков и настраиваемые правила. Кода внутри нет — движок читает манифест и применяет декларативные эффекты.

```
modules/
├── index.json            ← реестр: какие файлы загружать и в каком порядке
├── irreality-core.json   ← ядро, kind: core, выключить нельзя
├── isotope-tier.json     ← модуль сеттинга
└── my-setting.json       ← ваш модуль
```

Три источника загрузки (в порядке приоритета):
1. **Файлы** `modules/*.json` — основной путь на GitHub Pages.
2. **Встроенные копии** `assets/js/embedded.js` — резерв для `file://` и недоступных файлов. Генерируется скриптом, вручную не правится (§14).
3. **Локальная проверка** — файл, загруженный через кнопку в конфигурации; хранится только в вашем браузере, в репозиторий не попадает.

## 2. Минимальный модуль

```json
{
  "schema": "irreality.module/1",
  "id": "my-setting",
  "kind": "module",
  "name": "Мой сеттинг",
  "namespace": "my",
  "version": "1.0.0",
  "requires": ["irreality-core"],
  "description": "Что добавляет модуль.",
  "plates": [],
  "ammo": []
}
```

Подключение — запись в `modules/index.json`:

```json
{
  "schema": "irreality.module-registry/1",
  "modules": [
    { "id": "irreality-core", "file": "irreality-core.json", "required": true },
    { "id": "isotope-tier", "file": "isotope-tier.json" },
    { "id": "my-setting", "file": "my-setting.json" }
  ]
}
```

Поля записи реестра: `id` (должен совпадать с `id` манифеста), `file`, `required` (только для ядра), `example` (помечает модуль как «шаблон · не канон»).

## 3. Идентификация, зависимости, порядок

| Поле | Правила |
|---|---|
| `id` | Уникален в реестре. Латиница, kebab-case. |
| `namespace` | Уникален среди модулей. Формат: `^[a-z][a-z0-9-]{0,23}$`. Все сущности получают составные id: `my:my-plate`, `my:hot-slug`. Ссылки внутри своего модуля можно писать коротко (`"my-plate"`), на чужие — полностью (`"core:heavy"`). |
| `kind` | `core` — нельзя выключить, всегда первое; `module` — обычный. |
| `requires` | Массив id **обязательных** зависимостей. Модуль не включится без них; включение модуля автоматически включает зависимости; выключение зависимости каскадно выключает зависимых. |
| Порядок | Задаётся перетаскиванием в конфигурации. Нижние модули применяются поверх верхних: `carrierExtensions` расширяют носители, одноимённые сущности в разных namespace не конфликтуют. |

## 4. Настраиваемые правила (`rules`)

Правила появляются во вкладке «Правила», сгруппированные по модулю. Значения хранятся per-key вида `my:rustWear`.

```json
"rules": [
  { "id": "rustWear", "label": "Ржавчина: доп. износ", "hint": "Сколько Целостности теряется additionally за обстрел.",
    "type": "number", "default": 1, "min": 0, "max": 5 },
  { "id": "rustOn", "label": "Ржавчина включена", "type": "toggle", "default": true },
  { "id": "rustMode", "label": "Режим ржавчины", "type": "select", "default": "light",
    "options": [ { "value": "light", "label": "Лёгкая" }, { "value": "hard", "label": "Сильная" } ],
    "dependsOn": "my:rustOn" }
]
```

| Поле | Смысл |
|---|---|
| `type` | `toggle` / `number` / `select` — других типов UI нет. |
| `default` | Значение по умолчанию; отклонения от него считаются «изменёнными правилами» на ярлычке вкладки. |
| `min` / `max` | Границы числа (клампятся и в UI, и в движке). |
| `options` | Для select: `{value, label}`. |
| `dependsOn` | Полный ключ другого правила; пока оно ложно, контрол заблокирован. |
| `hint` | Подпись под контролом и текст в справочнике правил. |

Правила ядра доступны движку и по короткому ключу (`wearDivider`), и по полному (`core:wearDivider`). Правила модулей — **только по полному ключу**.

Эффекты ссылаются на значения правил через `rule` / `minRule` (§10) — так число из UI управляет эффектом без кода.

## 5. Словари пула (`attributes`, `skills`)

Два формата, можно смешивать:

```json
"attributes": [
  { "group": "Физические", "names": ["Сила", "Ловкость", "Выносливость"] }
],
"skills": ["Пси-фокус", { "group": "Ментальные", "names": ["Резонанс"] }]
```

Группы попадают в выпадающие списки конструктора пула как «Атрибуты · Физические». Плоская строка группируется под именем модуля. Дубликаты имён схлопываются. Игрок всегда может выбрать «Своё название / модификатор…» — словарь не ограничивает.

## 6. Типы урона (`damageTypes`)

```json
"damageTypes": [ { "id": "burn", "label": "Ожог", "short": "ОЖГ", "tone": "surf" } ]
```

Ядро объявляет `aggravated` и `surface`. Порядок объявления типов задаёт **очерёдность поглощения** бронёй. Тип используется в `ammo.damageType` и ключах `fixedDamage`.

**Ограничение:** большие карточки результата показывают только Усугублённый и Поверхностный. Свой тип участвует в расчёте, журнале и инвариантах, но отдельной крупной карточки для него нет — учитывайте это, если вводите экзотические типы.

## 7. Пластины (`plates`)

```json
{
  "id": "scrap", "code": "ХЛ", "name": "Хламовая плита",
  "defense": 2, "integrity": 10,
  "rounding": "ceil", "breakPenalty": 1,
  "firstShot": { "type": "defenseBonus", "value": 1 },
  "passive": { "text": "−1 Ловкость", "mods": { "agilityDice": -1 } },
  "effects": [
    { "type": "extraWear", "amount": 1, "rule": "my:rustWear",
      "when": { "ammoTag": "ballistic" }, "label": "Ржавчина" }
  ],
  "brokenNote": "Осыпается: 1 Поверхностный урон в час.",
  "notes": "Сварена из дорожных знаков."
}
```

| Поле | Смысл |
|---|---|
| `defense` | Вычитается из итогового урона; поглощённая часть изнашивает пластину. |
| `integrity` | Максимум Целостности. |
| `rounding` | `floor` / `round` / `ceil`. Не задано → правило ядра «Округление по умолчанию». |
| `breakPenalty` | Штраф к Защите при Целостности 0 (со следующего обстрела). Поглощение продолжается. |
| `firstShot` | `{"type":"defenseBonus","value":N}` или `{"type":"ignoreExcess"}`. Авто-срабатывание: полная Целостность + первый обстрел серии; в UI есть ВКЛ/ВЫКЛ. |
| `passive.text` | Показывается как предупреждение и в справочнике. |
| `passive.mods` | Движок понимает **только два ключа**: `agilityDice` (±кубики к пулу защиты) и `agilitySuccesses` (±успехи, применяются к броску защиты по правилу ядра). Остальные штрафы описывайте текстом. |
| `effects` | §10. |
| `brokenNote` | Флаг при поломке и при обстреле сломанной пластины. |
| `notes` | Справочная строка в карточке/таблице. |

## 8. Носители (`carriers`, `carrierExtensions`)

```json
"carriers": [
  { "id": "rig", "name": "Разгрузка", "plates": ["scrap"],
    "passive": { "text": "…", "mods": { "agilityDice": -1 } } }
],
"carrierExtensions": [
  { "target": "core:light", "addPlates": ["scrap"] }
]
```

`carrierExtensions` — единственный способ добавить свою пластину в чужой носитель. Вместимость/слоты не моделируются: одна пластина принимает весь обстрел.

## 9. Оружие (`weapons`, `weaponClasses`) и режимы (`fireModes`), укрытия (`covers`)

**`weapons` — та самая «база стволов».** Пресет «имя + Рейтинг + класс»:

```json
"weapons": [
  { "id": "obrez", "name": "Обрез", "rating": 5,
    "weaponClass": "core:shotgun-slug", "description": "Помпа, обрезанный ствол." }
]
```

Выбор ствола в UI подставляет `rating` и `weaponClass`; собственных модификаторов у ствола нет — всё остальное задаётся классом, режимом и патроном. Калибр в названии не пишется: он живёт в патроне.

**`weaponClasses`** — таблица дистанций:

```json
{ "id": "carbine", "name": "Карабин", "category": "auto",
  "bands": {
    "near": { "label": "0–40 м", "dice": 0 },
    "mid":  { "label": "40–150 м", "dice": 0 },
    "far":  { "label": "150–300 м", "dice": -2 }
  },
  "note": "…" }
```

`category` — одна из `pistol / smg / shotgun / auto / marksman` (используется режимом «Одиночный» и ограничениями «Дуплета»). `bands.*.rating` (как у дроби) **подменяет** введённый Рейтинг, пока включено правило ядра `autoShotRating`.

**`fireModes`:**

```json
{ "id": "salvo", "code": "ЗЛ", "name": "Залп", "cost": "2 патрона",
  "poolMod": -1, "poolModByCategory": { "auto": -2, "default": 0 },
  "damageBonus": 1,
  "aim": { "perTurn": 1, "max": 2 },
  "headshot": { "dice": -2, "damage": 2 },
  "overpenetration": { "margin": 5, "damage": 2, "damageType": "surface" },
  "ricochet": { "halfRating": true },
  "area": "линия 3 м", "selfPenalty": "−1 кубик в следующий ход",
  "shooterCover": "+2 к Защите стрелка",
  "requires": { "categories": ["shotgun"], "bands": ["near"] },
  "note": "…" }
```

Все поля необязательны. `requires` не запрещает расчёт — выдаёт предупреждение мастеру. Режим **никогда не умножает износ**: один обстрел — одно списание Целостности.

**`covers`:** `{ "id", "name", "dice", "untargetable": true, "note" }` — кубики к пулу защиты; `untargetable` запрещает атаку.

## 10. Патроны (`ammo`) и эффекты

```json
{
  "id": "hot-slug", "code": "ГП", "name": "Горячая пуля",
  "damageType": "aggravated",
  "damageBonus": 1, "damageVsArmor": 0,
  "attackDice": -1, "armorPierce": 1,
  "ignoreWearDivision": false,
  "fixedDamage": { "aggravated": 2, "surface": 1 },
  "surfaceBypass": true,
  "tags": ["fire", "ballistic"],
  "effects": [ { "type": "note", "text": "Поджигает: …", "when": {} } ],
  "description": "…"
}
```

| Поле | Смысл |
|---|---|
| `damageType` | Тип формульного урона (по умолчанию `aggravated`). |
| `damageBonus` | ± к формульному урону, безусловно. **Не применяется к `fixedDamage`.** |
| `damageVsArmor` | ± к урону только при броне (дробь: −2). |
| `attackDice` | ±кубик к пулу атаки против брони/укрытия (JHP −1, AP +1). В дайджесте показывается приглушённым, если цель открыта. |
| `armorPierce` | Игнорирует N Защиты — уменьшает и поглощение, и износ. Применяется **после** бонуса первой пули. |
| `ignoreWearDivision` | Поглощённое не делится на делитель износа. |
| `fixedDamage` | Урон из описания вместо формулы (правило `fixedDamageReplaces` может добавить формулу сверху). |
| `surfaceBypass` | Поверхностный урон идёт и в Здоровье, и в Целостность (шоковая волна). |
| `tags` | Метки для условий эффектов (`nuclear`, `ballistic`, `shot`, свои). |

**Типы эффектов** (у пластин и патронов):

| Тип | Параметры | Что делает |
|---|---|---|
| `reduceDamage` | `damageType`, `amount`, `min`, `rule`, `minRule`, `when`, `label` | Снижает урон этого типа **после поглощения**, не ниже `min`. Только у пластин. |
| `extraWear` | `amount` / `rule`, `when`, `label` | Доп. износ Целостности за обстрел. Только у пластин. |
| `zeroIntegrity` | `target`, `label` | **Нарративный флаг** («киберимпланты → 0»), числа не меняет. |
| `note` | `text`, `when` | Предупреждение мастеру. |

`rule` / `minRule` — полный ключ правила; его текущее значение из UI переопределяет `amount` / `min`. Неизвестные типы эффектов не роняют расчёт: у патронов попадают в предупреждения, у пластин игнорируются.

**Условия `when`:** `ammoTag`, `ammoId`, `armored` (true/false), `broken` (true/false). Пустой объект — всегда. Комбинируются по И.

## 11. Порядок вычислений (что на что влияет)

```
Разница = атака − защита;  ≤ 0 → промах (урона и износа нет)
Рейтинг: введённый ИЛИ bands.rating (если autoShotRating)
Урон = Рейтинг + Разница
       + ammo.damageBonus
       + ammo.damageVsArmor (если броня)
       + mode.damageBonus + headshot.damage
       → кламп ≥ 0 → правило minDamage
   (fixedDamage: значения из описания; формула добавляется только если fixedDamageReplaces = false)
Защита = plate.defense − breakPenalty (если сломана)
         + firstShot.bonus → − armorPierce → + прочность укрытия (правило) → кламп ≥ 0
Поглощено = min(урон без шоковой волны, Защита); остаток → Здоровье
reduceDamage пластины → снижение остатка (минимум)
ignoreExcess → остаток (кроме шоковой волны) гасится
Износ = Поглощено ÷ wearDivider, округление пластины/ядра
        (ignoreWearDivision или делитель 1 → целиком)
        + шоковая волна + extraWear → Целостность = max(0, было − износ)
Целостность 0 → флаг поломки; breakPenalty действует со СЛЕДУЮЩЕГО обстрела
```

## 12. Валидация

При загрузке (`modules.js`) проверяется: наличие `id`/`name`, формат `namespace`, `kind`, массивы_known_полей, `id`/`defense`/`integrity` у пластин, `id` у патронов, `id`/`type` у правил. Скрипт сборки дополнительно ловит: дубликаты id и namespace, расхождение id реестра и манифеста, отсутствующие зависимости, отсутствие ядра, формат словарей.

Ошибки → модуль пропускается с записью в «Отчёт загрузки» на экране конфигурации. Предупреждения не блокируют.

## 13. Настройка через интерфейс

- **Экран конфигурации** (при первом входе и по кнопке «Модули»): тумблеры, зависимости, перетаскивание порядка, источник (файлы/embedded/локальный), отчёт загрузки.
- **Вкладка «Правила»**: все правила активных модулей; изменения применяются мгновенно и сохраняются между сессиями.
- **Локальная проверка**: кнопка в конфигурации загружает JSON только в ваш браузер — удобно при написании модуля; для публикации — файл в `modules/` + реестр.

## 14. Сборка и публикация

```bash
python tools/build_embedded.py            # пересобрать embedded.js из modules/*.json
python tools/build_embedded.py --check --no-stamp   # CI-проверка актуальности
python -m http.server 8080                # локальный сервер (иначе работает резерв)
```

После любой правки JSON — пересборка, иначе `file://` покажет старые числа. Публикация: commit → GitHub Pages (`Deploy from a branch`, root).

## 15. Известные ограничения движка

Честный список, чтобы не проектировать модуль вокруг того, чего нет:

1. Эффектов всего четыре; произвольной логики нет.
2. `passive.mods` понимает только `agilityDice` и `agilitySuccesses`.
3. Крупные карточки результата — только Усуг/Пов (§6).
4. Переключатель «абляция только против ядерных» реализован как частный случай ключа `iso:nuclearOnly` — в своём модуле делайте отдельное правило и условие `when`, не рассчитывайте на этот ключ.
5. `damageBonus`/`damageVsArmor` не работают с `fixedDamage`.
6. Одна пластина на цель; локаций и слотов нет.
7. `weapons` — только пресет Рейтинга и класса.
8. Типы правил — только toggle/number/select.

## 16. Чек-лист нового модуля

- [ ] `id`, `namespace` уникальны; namespace строчный латинский.
- [ ] `requires: ["irreality-core"]`.
- [ ] Запись в `index.json`, id совпадает с манифестом.
- [ ] Пластины: числа protection/integrity, округление осознанно (или наследуется).
- [ ] Ссылки на чужие сущности — с namespace (`core:heavy`).
- [ ] Правила имеют `default`, эффекты ссылаются на них через полные ключи.
- [ ] Теги патронов согласованы с условиями `when`.
- [ ] `python tools/build_embedded.py` — без ошибок; `--check` в CI зелёный.
- [ ] Прогон через локальную проверку + сценарии из протокола ручной приёмки для затронутых механик.

## 17. Полный пример

`modules/wasteland.json`:

```json
{
  "schema": "irreality.module/1",
  "id": "wasteland",
  "kind": "module",
  "name": "Пустошь",
  "namespace": "wl",
  "version": "1.0.0",
  "author": "Vireist",
  "description": "Ржавые плиты, горячие пули и обрез.",
  "requires": ["irreality-core"],
  "skills": ["Ремонт хлама"],
  "rules": [
    { "id": "rustWear", "label": "Ржавчина: доп. износ за обстрел",
      "hint": "Плита крошится от любого попадания.", "type": "number", "default": 1, "min": 0, "max": 4 }
  ],
  "carrierExtensions": [ { "target": "core:light", "addPlates": ["scrap"] } ],
  "plates": [
    { "id": "scrap", "code": "ХЛ", "name": "Хламовая плита",
      "defense": 2, "integrity": 10, "rounding": "ceil", "breakPenalty": 1,
      "effects": [
        { "type": "extraWear", "amount": 1, "rule": "wl:rustWear", "when": {}, "label": "Ржавчина" }
      ],
      "brokenNote": "Осыпается ржавой крошкой.", "notes": "Округление вверх — плита хрупкая." }
  ],
  "ammo": [
    { "id": "hot-slug", "code": "ГП", "name": "Горячая пуля",
      "damageType": "aggravated", "damageBonus": 1, "armorPierce": 1,
      "tags": ["fire"], "description": "+1 урон, игнорирует 1 Защиты. Поджигает цель." }
  ],
  "weapons": [
    { "id": "obrez", "name": "Обрез", "rating": 5,
      "weaponClass": "core:shotgun-slug", "description": "Помпа с обрезанным стволом." }
  ]
}
```

Запись в реестр → пересборка embedded → модуль появится на экране конфигурации, «Обрез» — в базе стволов, «ХЛ» — в лёгкой броне, правило «Ржавчина» — во вкладке «Правила».
